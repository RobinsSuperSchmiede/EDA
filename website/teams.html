Why teams use it

Keep your stack
Gain a product

reuse

No rewrite

Keep React, Vue, Svelte or plain HTML, and a backend in Python, Node.js, Java, C++, Go, Rust or .NET. openshell init reads your project and writes the config. There is no desktop code to maintain.

ship

Installers, signing, updates

Branded installers for every system, per-user installs without admin rights, an MSI for software distribution, signing settings and an update check. One tag publishes everything.

govern

AI on a leash

Agents get permission scopes per mode, critical actions wait for a human, every call lands in an audit log. No agent runs arbitrary commands.

own

Your stack, your data

MIT licensed, no cloud service, no per-seat fee. Data stays on the user's machine. The shell is never compiled into your app, so a shell update improves every app.

Rollout

From web app
To every desktop

Five steps, most of them one command. Your CI does the heavy lifting on a tag.

01 · wrap

Describe

openshell init detects frontend and backend and writes openshell.json.

02 · package

Build installers

openshell package with your name and icon. Add --target bundle for the portable file.

03 · sign

Remove warnings

A Windows certificate or signing command, macOS identity and notarisation. Bring your own certificates.

04 · publish

Tag a version

openshell release workflow writes a CI workflow that builds all systems and publishes a download page.

05 · update

Tell users

package.update_url and openshell update return the right download for each system.

Security and governance

What your security team
will ask about

ControlWhat it doesSetting
Opt-inAgents are off until the app sets agents.enabled. Off means: no MCP, no tools API, no UI bridge, no gateway MCP.agents.enabled
Agent sessionsEach agent gets its own token (stored hashed) and scopes, never more than the app grants; audited by name, revocable at once.openshell agents token
Permission scopesEvery agent tool needs exactly one of seven scopes: read, ui, actions, services, files, code, system. Production grants fewer than development.agents.permissions
Human approvalScopes you list need a decision. The app shows a dialog; unanswered requests are denied.agents.approval_required
Audit logEvery call, allowed, denied or failed, with agent name, channel, tool, scope, arguments and duration, as lines of JSON..openshell/audit.jsonl
File accessProject-scoped. Absolute paths, .., symlink escapes and OpenShell's own state are rejected; .git is protected.built in
No shell for agentsAgents cannot run arbitrary commands. Only tasks you declare, under the system scope.tasks
Control APILoopback only, bearer token, Host and Origin checks against DNS rebinding and other websites.built in
Database accessPer database: none, read or write. Reads are read-only SQL.agent_access
Remote accessOff by default. Per-device tokens stored as hashes, IP and CIDR allowlist, TLS, rate limit with lockout, audited with the device name.runtime.remote
Know the limits. The permission layer governs cooperating agents. OpenShell is not a sandbox against malware running as the same user. Exposed TCP ports have no login of their own, and exposed HTTP ports check the token on the first request of a connection. Rate limits live in memory.
Reporting. Vulnerabilities go through private GitHub security advisories, not public issues. You can expect an acknowledgement within a few days. Read the security policy and the architecture for the threat model.
Fit

A good fit
And where to wait

Works well today

  • Internal tools and dashboards that deserve a real desktop presence
  • Local-first apps with the built-in SQLite database
  • Existing web apps with any frontend framework and a backend that follows the app contract
  • Tools your AI assistants should use, with limits and an audit trail
  • Mixed teams on Windows, macOS and Linux

Plan around

  • Bundled runtimes are built per system: build installers on each OS (the release workflow does)
  • Automatic installation of updates is planned; today you get the check and the download
  • Agent sessions and device scopes are new: on main, part of the next release
  • Phones: the Android app is not in the Play Store and has not been verified on a device
  • Alpha status: the config format may change before 1.0
