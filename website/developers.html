Quick start

Five minutes to
a desktop app

Create, run, ship. Or point OpenShell at the web app you already have: init detects Vite, Next.js, Angular, Vue, Python, Node.js, Go, Rust, Java and C++.

No release yet for your system, or you want the latest? Download or build from source.

# install (Windows: scripts/install.ps1) curl -fsSL https://raw.githubusercontent.com/RobinsSuperSchmiede/EDA/main/scripts/install.sh | sh $ openshell create my-app --with frontend,database $ cd my-app $ openshell dev # native window, hot reload $ openshell package # installer # existing project $ openshell init $ openshell doctor
Anatomy

One file
Describes the app

Your frontend and backend stay normal projects. OpenShell reads openshell.json, starts what is in it and never compiles your code into the shell.

{
  "version": 1,
  "app": { "name": "My App", "version": "1.0.0", "icon": "assets/icon.png" },
  "frontend": {
    "command": "npm run dev -- --port ${port} --strictPort",
    "cwd": "frontend",
    "port": "auto",
    "url": "http://127.0.0.1:${port}",
    "setup": { "command": "npm install", "creates": "frontend/node_modules" },
    "build": "npm run build",
    "dist": "frontend/dist",
    "proxy": { "/api": "${services.backend.url}" },
    "depends_on": ["backend"]
  },
  "services": [
    {
      "name": "backend",
      "command": ["python", "main.py"],
      "cwd": "backend",
      "port": "auto",
      "healthcheck": "http://127.0.0.1:${port}/health",
      "openapi": "/openapi.json",
      "watch": ["backend"]
    }
  ]
}

The app contract

Five rules, and your code runs unchanged inside and outside OpenShell.

  • Read your port from PORT and bind 127.0.0.1
  • Answer GET /health with a 200 when ready
  • Store data in OPENSHELL_DATA_DIR, so it survives updates
  • Call the backend with relative /api URLs; OpenShell proxies them
  • Offer functions to agents with capabilities, an openapi document or frontend actions

Building blocks

Use what you need

Frontend, backend, database and functions for agents are independent. Combine them when you create the app or add them later, in any order.

frontend

Any web UI

Dev server with hot reload, or a production build served by OpenShell with an /api proxy.

backend

Your language

Anything that serves HTTP on localhost. Health checks, restarts with backoff, rebuilds on change, logs, CPU and memory.

database

Built-in SQLite

Migrations, an SDK and per-database agent access. A UI can keep its data without a backend.

functions

Scripts as tools

A program per call: JSON in, JSON out. An AI interface without any server.

openshell create notes --with frontend,database     # UI plus built-in SQLite, no backend
openshell create tools --with functions             # functions for AI agents only: no UI, no server
openshell add backend --lang node                   # add blocks later, in any order

Frontend SDK

Optional, and
never in the way

The SDK is served by the shell at /sdk.js. Your frontend works unchanged without it; with it you reach the runtime, the window, the database and the agent layer.

const { OpenShell } = await import(`${window.__OPENSHELL__.api}/sdk.js`);

await OpenShell.db.query("SELECT * FROM notes WHERE done = ?", [0]);
await OpenShell.notify("Export finished", "Saved to reports/q3.pdf");
await OpenShell.runtime.restart("backend");

// let agents drive your UI
OpenShell.agent.registerAction(
  "set_filter",
  { description: "Show all, open or done todos", permission: "ui" },
  ({ filter }) => setFilter(filter),
);

Calls are checked against agents.sdk_permissions. Reference: frontend SDK.

Beyond the desktop

Same app
On a server or a phone

{
  "services": [
    { "name": "compiler", "command": ["cargo", "watch"],
      "platforms": ["desktop", "server"] },
    { "name": "sync", "command": ["node", "sync.js"],
      "background": "pause" }
  ],
  "runtime": {
    "remote": {
      "enabled": true,
      "allow": ["192.168.1.0/24"],
      "tls": { "enabled": true },
      "shared_token": false
    }
  }
}
  • Platform adapters decide which programs may start. Desktop and server start anything; on Android only system tools and programs shipped with the app.
  • Lifecycle: a service with "background": "pause" pauses in the background and resumes when the app returns.
  • Remote gateway: other devices call your app's functions over MCP, or reach exposed services, with a token per device.
  • Termux: the CLI runs on a phone with anything you pkg install.
