Platform milestones: Android, universal shell, secure remote access

This plan splits the platform work (Android, one download per system, apps built on the phone, secure remote access, Play Store) into milestones. Each milestone builds on its own, has tests and is documented. The last section lists what cannot be finished inside this repository.

Status legend: ✅ done · 🚧 partial · ⏳ open

M1 – Secure remote gateway and exposed services ✅#

Goal: reach the phone's (or any host's) websites, APIs and services from another computer over IP address and port, with security features that can be switched on one by one.

FeatureConfigDefault
Bind address and portruntime.remote.bind, runtime.remote.port0.0.0.0:7420

Code: crates/config/src/model.rs (RemoteConfig, ExposeConfig, RateLimitConfig, TlsConfig), crates/core/src/remote/*, openshell remote … in the CLI.

M2 – Apps on the phone (Termux) ✅#

Goal: openshell create, dev, start, package --target bundle on the phone; Python, Node, Java, Rust, Go … from Termux packages run as services, setup and build steps.

  • TermuxAdapter (crates/runtime/src/platform.rs): platform android, processes: full, programs from $PREFIX/bin and the project, shell $PREFIX/bin/sh, wake_lock capability. Picked automatically inside Termux; OPENSHELL_ANDROID_MODE=app|termux overrides.
  • openshell doctor gives pkg install … hints per language on Termux.
  • openshell start/dev take a Termux wake lock (termux-wake-lock) while services must stay alive.

M3 – Universal shell: one link per system ✅ (🚧 Android link)#

Goal: a developer builds once; users download one file per system, the program is unchanged.

  • openshell package --target bundle: a portable, platform-neutral app bundle (<app>-<version>.osapp, a zip with openshell.json and the app files) – runs with openshell start --bundle on any host, including Termux, and is what the Android app imports.
  • openshell package --manifest <base-url>: writes downloads.json (version, file, size, SHA-256 per platform) and a download.html page that picks the visitor's system.
  • openshell package --ci github: writes .github/workflows/openshell-release.yml into the app – one tag push builds Windows, macOS (arm64 + x64), Linux installers and the bundle in parallel and publishes them with the manifest as a GitHub release.
  • Code signing (package.signing: Windows certificate thumbprint / sign command, macOS signing identity) is passed to the bundler.
  • Update check: package.update_url points at the downloads.json of the newest release; the installed app reports a newer version (GET /v1/update, openshell update --check).

M4 – Native Android app and Play Store 🚧#

Goal: an Android app (AAB) that can be published in the Play Store.

  • crates/android (openshell-android, cdylib libopenshell_android.so): JNI bridge that starts the unchanged core headless with an AndroidAdapter for the APK's native library directory and forwards lifecycle events.
  • apps/android/ – Gradle project (Kotlin): MainActivity (WebView on the app's frontend), RuntimeService (foreground service type specialUse, notification with running services, battery-optimisation request), app bundle import, targetSdk 36, 16 KB page-size aligned native libraries, release signing from keystore.properties / environment, bundleRelease → AAB.
  • apps/android/store/ – listing texts, data-safety answers, foreground-service justification.
  • CI workflow android-app.yml builds the Rust library for arm64/x86_64 and the AAB.

M5 – Docs, roadmap, changelog ✅#
