Changelog

All notable changes to this project are documented here. The format follows Keep a Changelog and the project uses Semantic Versioning.

Unreleased#

Changed (breaking)#

  • AI agents are opt-in. agents.enabled defaults to false. While it is off, /mcp, /mcp/app, the tools API, the UI bridge and the remote gateway's MCP endpoint refuse every request and no bridge script is injected; the app, the frontend SDK and exposed services keep working. Templates, openshell create, openshell init and openshell add function write "enabled": true; openshell agents enable / disable switch it. Existing apps that use agents need "agents": { "enabled": true } – openshell doctor warns when agent settings are present without it.

Added#

  • Bundled runtimes (runtimes in openshell.json): ship Python (python-build-standalone), Node.js (nodejs.org) or a Java JRE (Eclipse Temurin) inside the app. openshell runtime add|install|remove downloads them into the project with SHA-256 verification; their executable folders come first in PATH for every service, setup and build step, function and task, and openshell package ships them. The app release workflow installs them on every build machine.
  • Version requirements (services[].requires, frontend.requires): { "python": ">=3.10, <3.14" } for python, node, java, dotnet, go, rust. openshell doctor reports mismatches as errors (bundled runtimes included), the app logs them as warnings when it starts. openshell init proposes requires from the version it finds.
  • Languages as data: one entry per runtime and language (programs, version probe, bundle layout, support level, templates) in openshell_config::runtimes, one detector per language in crates/cli/src/languages/. New: openshell languages, openshell create --list shows language and support level, openshell init detects .NET (*.csproj, ASP.NET Core, Swashbuckle OpenAPI). openshell doctor lists runtimes from the same table.
  • Agent sessions with their own tokens and scopes: `openshell agents token <name> [--scopes read,actions] [--full],openshell agents tokens,openshell agents revoke <name>. Tokens (osa_…`) are stored hashed, reach only /mcp/app (or with --full also /mcp and /v1/tools), never get more than agents.permissions grants, are audited as session:<name> and stop working at once when revoked. openshell mcp --token / OPENSHELL_AGENT_TOKEN (also for installed apps' --mcp).
  • Permissions per device: openshell remote pair <device> --scopes read (also scopes in POST /v1/remote/devices).
  • Effective permissions: openshell agents, GET /v1/agents and a new AI agents section in the desktop runtime panel (scopes per mode, approvals, sessions and devices with what they effectively may do); the title-bar menu shows when agents are off. Denials name the session's or device's scopes.
  • Template end-to-end tests: scripts/e2e-templates.py creates every template, runs it headless, waits for healthy services, loads the frontend and calls an agent function; CI runs it on Windows, macOS and Linux (job templates). CI also checks that the generated website is up to date.
  • Building blocks: frontend, backend, database and agent functions are independent and freely combinable. openshell add frontend | backend [--lang] | database [name] | function <name> adds a block to an app; openshell create <name> --with frontend,database,… composes a new one (interactive selection in a terminal).
  • Built-in databases (databases in openshell.json): SQLite files in the app's data directory, migrations, OPENSHELL_DB_<NAME> / DATABASE_URL for services, OpenShell.db.query/execute/schema/list for the frontend, agent tools db_list, db_schema, db_query (read-only), db_execute, per-database agent_access.
  • Script functions: capabilities with "run" execute a program per call (JSON on stdin, result on stdout) – an app can offer an AI interface without any server. OpenShell.invoke(name, input) in the SDK.
  • Apps without a frontend show a console in the window (services, database browser, functions with "Run", agent commands, logs); window.enabled: false runs an app in the tray only.
  • MCP resources (status, config, logs, capabilities, database schemas) and notifications/tools/list_changed from openshell mcp.
  • runtime.launch_at_login for installed apps.
  • openshell status and openshell doctor show databases and functions.
  • Platform-neutral core for desktop, server and Android: a RuntimeAdapter builds every command and reports the platform's capabilities (platform in /v1/status, /v1/health and the agent tool app_info). The AndroidAdapter runs system tools and programs bundled with the app and explains what to use instead of anything else. The core and the CLI build for Android (new CI job); verified headless on an Android 16 emulator.
  • services[].platforms (desktop, android, server) and services[].background (keep / pause).
  • App lifecycle events (foreground, background, low_memory, power_save, network) via Shell::lifecycle, POST /v1/lifecycle and openshell lifecycle; paused services resume in the foreground.
  • Remote gateway (runtime.remote): other devices use the app's functions over MCP with a pairing token; openshell remote prints URL, token and an MCP client configuration. See docs/platforms.md.
  • Remote security (all optional): per-device tokens (openshell remote pair <device> with QR code and pairing URI, devices, revoke), runtime.remote.allow (IP / CIDR allowlist), rate_limit with lockout after failed logins (openshell remote unblock), tls (self-signed with pinned SHA-256 fingerprint, or own certificate), shared_token: false, and remote access audited with the device name. See docs/remote-access.md.
  • Exposed services (runtime.remote.expose): make a service or the frontend reachable from other devices on its own port – http with token login (header, cookie or one-time ?openshell_token=) or raw tcp (databases, MQTT …) protected by the allowlist.
  • Termux: the TermuxAdapter runs everything installed with pkg install (Python, Node.js, Java, Rust, Go, databases), holds a Termux wake lock while an app runs, and openshell doctor gives pkg install hints. Platform capabilities report toolchains and wake_lock. Release builds include the CLI for aarch64-linux-android and Linux arm64; install.sh detects Termux.
  • Portable app bundles: openshell package --target bundle writes <app>-<version>.osapp (also on Android); openshell install <file> [--start] and openshell apps run bundles on any host, keeping app data across updates.
  • One download link per system: openshell release workflow writes a GitHub Actions workflow that builds Windows, macOS (arm64, x64), Linux installers and the bundle on a tag push; openshell release manifest writes downloads.json and a download page that picks the visitor's system.
  • Code signing (package.signing.windows / .macos) and update checks (package.update_url, openshell update, GET /v1/update).
  • Android app (apps/android, Kotlin) with the JNI bridge openshell-android (crates/android): app manager for .osapp bundles, WebView, foreground service (specialUse) with notification and wake lock, lifecycle and network events, target SDK 36, 16 KB page-size aligned native library, AAB build and signing in CI (android-app.yml), Play Store listing, policy answers and privacy policy template. See docs/android-app.md.
  • Website in website/: a landing page (ASCII field of code glyphs, architecture diagram, product gallery, platforms, shipping, security) with a "find your way" section, plus pages for users (use.html), teams and companies (teams.html), developers (developers.html) and AI agents (agents.html), a download page that detects the visitor's system, and the documentation (website/docs/, searchable, rendered from docs/*.md, the roadmap, the changelog and the project documents). python scripts/build-website.py renders the docs and keeps the shared header and footer in sync (--check for CI). dev.html adds a customize bar to try colour themes (green, light blue, red, purple, amber, mono), hero variants, surfaces and background settings; index.html is the production landing page.

0.2.1 - 2026-11-19#

Fixed#

  • HTML5 drag and drop works in the app window: Tauri's drag and drop handler is off, so dragover and drop reach the page (on Windows they did not). Files dropped on the window arrive as in a browser (dataTransfer.files).

0.2.0 - 2026-11-19#

Added#

  • window.title_bar: "overlay": the frontend draws its own title bar. Windows and Linux get a window without the system title bar (edges still resize), macOS keeps its window buttons over the content. The desktop window offers window.__OPENSHELL__.window (minimize, toggleMaximize, close, isMaximized, showMenu, plus title_bar and os); elements with data-tauri-drag-region move the window. The window permissions are granted at runtime to the app's frontend origin only. OpenShell's loading screen shows a minimal title bar in this mode.
  • The title bar menu (services, reload, window actions) is available on every platform via showMenu().

0.1.0 - 2026-11-17#

First public alpha.

Added#

  • Tauri 2 desktop shell: window, WebView, loading screen, runtime panel, tray, notifications, approval dialogs, single instance, title bar right-click menu with live service monitoring (Windows).
  • Runtime manager: services in dependency order, setup and build steps, HTTP/TCP health checks, restart policies with backoff, logs, dynamic ports and ${...} variables, static frontend server with reverse proxy, file watching, CPU/memory metrics, process-tree cleanup.
  • Agent Interaction Layer: 28 tools over MCP (stdio and HTTP) and HTTP/JSON, developer and app profiles, semantic UI bridge, capabilities (config, OpenAPI import, frontend actions), permission scopes, approvals, audit log, AI provider discovery.
  • CLI: init, create, dev, start, stop, run, restart, status, logs, doctor, build, package, mcp, tools, call, approvals, approve, deny, audit, schema, guide.
  • openshell package: NSIS/MSI, DMG, DEB/RPM/AppImage installers with app name and icon.
  • Templates: vanilla-python, react-python, react-node, vue-python, svelte-go, vanilla-java, vanilla-cpp, custom.
  • Frontend SDK @openshell/sdk.
  • AI-harness support: AGENTS.md, CLAUDE.md, llms.txt / llms-full.txt, the AI app development guide (openshell guide) and a Claude Code skill; every new project gets its own AGENTS.md.
  • Release workflow with prebuilt binaries for Windows, macOS (arm64, x86_64) and Linux, plus install scripts.
