OpenShell for AI agents

OpenShell is designed to be worked on by AI agents in three ways. This folder contains the material that makes AI harnesses productive with it.

Role of the agentWhat it getsStart here
Builds a new app on OpenShell (coding agent)app contract, workflow, verification commands, config cheat sheetBuilding apps with AI · openshell guide
Develops a running app (coding agent connected to it)32 MCP tools: status, logs, services, databases, files, UI automationAgent Interaction Layer · openshell mcp
Uses an app (assistant)only the app's own functionsAgent Interaction Layer · openshell mcp --app / my-app.exe --mcp

Setup recipes#

Claude Code#

# make the skill available in all projects
mkdir -p ~/.claude/skills/openshell
cp docs/ai/skills/openshell/SKILL.md ~/.claude/skills/openshell/

# connect a running app (develop) or an app to use
claude mcp add my-app-dev -- openshell mcp --project /path/to/my-app
claude mcp add my-app     -- openshell mcp --app --start --project /path/to/my-app

Codex / Cursor / other agents#

Open the app folder – the generated AGENTS.md is picked up automatically. For an MCP connection use {"command": "openshell", "args": ["mcp", "--project", "/path/to/my-app"]}.

Agents without file access to this repository#

Point them to llms-full.txt, or let them run openshell guide – the guide ships inside the CLI, so it always matches the installed version.

Example prompts#

Build a desktop app with OpenShell: a time tracker with a Svelte frontend and a Go backend. Projects and time entries are stored locally; AI agents must be able to start and stop timers and get a weekly report.

This folder contains a React + FastAPI project. Turn it into an OpenShell desktop app, import the FastAPI routes as agent capabilities and create a Windows installer.

Our OpenShell app's backend crashes on startup. Find out why and fix it. (with openshell mcp connected)

Writing apps that agents can use well#

  • One capability per user intention (add_expense, monthly_summary), not per database table.
  • Descriptions say what the function does and what it returns; inputs have JSON Schemas with required.
  • Queries get "permission": "read", changes "actions" – production mode grants exactly these by default.
  • Return JSON objects with ids, so agents can chain calls.
  • Keep UI-only state (filters, selected item) as frontend actions (registerAction) with "permission": "ui".
