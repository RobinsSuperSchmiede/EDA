Configuration reference (openshell.json, version 1)

OpenShell looks for openshell.json or openshell.toml in the given directory and its parents. All relative paths are resolved against the directory containing the file. Unknown fields are errors (typos are caught early). Editor completion: add "$schema": "https://raw.githubusercontent.com/RobinsSuperSchmiede/EDA/main/schema/openshell.schema.json". openshell schema prints the schema; openshell doctor validates the file and the environment.

frontend#

OpenShell does not care which framework you use. It needs one of:

  • command + url (or port): a process that serves the frontend (dev server, local web server),
  • url alone: an already running or remote frontend,
  • dist: a directory of built files that OpenShell serves itself.
FieldDescription
commandShell string ("npm run dev") or argv array
cwdWorking directory
envExtra environment variables (values support ${...})
portNumber or "auto"; available as ${port} and $PORT
urlURL loaded into the window
distBuilt frontend directory (production)
buildBuild command for openshell build
setupOne-time step, e.g. { "command": "npm install", "creates": "frontend/node_modules" }
proxyStatic server reverse proxy, e.g. { "/api": "${services.backend.url}" }
watchPaths that reload the window when changed (dev mode; useful for static frontends)
healthcheckOverride readiness check (default: the URL answers)
depends_onServices that must be healthy first
productionOverrides for production mode: { "command", "url", "dist" }

Mode selection: development uses command/url, falling back to dist. Production uses production overrides, then dist, then the development settings.

runtimes#

Language runtimes shipped inside the app, so the user's machine needs no Python, Node.js or Java:

"runtimes": {
  "python": "3.12",
  "node": { "version": "22", "path": "vendor/node" },
  "java": "21"
}
RuntimeDownloaded fromDefault version
pythonpython-build-standalone (install_only builds)3.12
nodenodejs.org22
javaEclipse Temurin JRE (adoptium.net)21

A value is a version ("22", "3.12", "21.0.5") or { "version", "path" } (default path runtimes/<name>, inside the project). openshell runtime install downloads every declared runtime for the current system and checks its SHA-256; openshell runtime add <name> [version] declares and downloads in one step. The runtime's executable folders are put in front of PATH for every service, setup and build step, function and task, so python main.py or npm install use the bundled copy. openshell package ships the folder with the app. A runtime is built for one operating system: build installers on each system (the release workflow runs openshell runtime install there). Downloaded runtimes do not belong in git; runtime add adds the folder to .gitignore.

capabilities[]#

{
  "name": "add_todo",
  "description": "Create a todo",
  "permission": "actions",
  "input_schema": { "type": "object", "properties": { "title": { "type": "string" } }, "required": ["title"] },
  "http": { "service": "backend", "method": "POST", "path": "/api/todos" }
}

Exactly one target:

  • http – service + path, or url; GET/DELETE send the input as query parameters, other methods as JSON body.
  • run – a script/program: ["python", "tools/x.py"] or { "command", "cwd", "env", "timeout_ms" }. It receives the input as JSON on stdin (and in OPENSHELL_INPUT) and prints its result (JSON or text) on stdout; a non-zero exit code is an error (message from stderr). No server needed – see Building blocks.
  • task – name of a task (input is ignored).

Agents see each capability as a tool cap_<name> (developer profile), under its plain name (app profile) and via app_invoke. The frontend calls them with OpenShell.invoke(name, input).
