What you get

A normal app
That respects you

install

Like any other app

A setup file on Windows, a disk image on macOS, a package or AppImage on Linux. On Windows it installs for your user and needs no admin rights.

data

Your files stay yours

Every app keeps its data in a folder of your user account. Nothing in OpenShell needs an account or a cloud service.

background

Quiet when you want it to be

Apps can sit in the tray, keep working when the window is closed and start at login. Right-click the title bar to see what is running.

assistants

AI helps only if you let it

Assistants can use the app's own functions, never your screen. Changes can wait for your approval, and every call is recorded.

Install

Get the app
From whoever made it

There is no app store. You get an OpenShell app from its publisher, usually from a download page that offers your system first. You do not need to install OpenShell separately: the installer contains it.

01

Download

Get the setup.exe from the publisher's page.

02

Run it

It installs for your user in a few seconds. No administrator password.

03

Open

Start the app from the Start menu. Windows 11 already has what the window needs.

If Windows says “Windows protected your PC”, the installer is not signed. Choose More info, then Run anyway, only if you trust the publisher.

01

Pick your Mac

There is a build for Apple Silicon (M-series) and one for Intel Macs.

02

Open the .dmg

Drag the app into Applications.

03

Open

Start it from Applications or Spotlight.

If macOS says the app cannot be opened because the developer is unverified, the app is not notarised. Right-click it, choose Open, and confirm, only if you trust the publisher.

01

AppImage

Make it executable and run it. No installation needed.

02

Or a .deb package

Install it with your package manager and start it from the menu.

03

WebKitGTK

The window uses WebKitGTK 4.1. Most desktops have it; if not, install it first.

chmod +x my-app_1.2.0_amd64.AppImage && ./my-app_1.2.0_amd64.AppImage
sudo apt install ./my-app_1.2.0_amd64.deb        # Debian, Ubuntu
sudo apt install libwebkit2gtk-4.1-0             # only if the window does not open
Not in the Play Store yet. The OpenShell app for Android is written and builds in our CI, but has not been tested on a real phone and is not published. Until then there is a way for the technically inclined.

Install Termux, then install the OpenShell command line and add the app's .osapp file. The app runs in the background; open its address in the phone's browser.

curl -fsSL https://raw.githubusercontent.com/RobinsSuperSchmiede/EDA/main/scripts/install.sh | sh
openshell install my-app-1.2.0.osapp --start

Some publishers offer a portable .osapp file. It runs on every system that has the OpenShell command line, including servers and Termux. Your data stays put when you install a newer version.

openshell install my-app-1.2.0.osapp --start
openshell apps                                  # list installed apps

Get the command line from the download page.

Does the app need anything else? Apps written in Python, Node.js or Java need that runtime on your computer unless the publisher ships it with the app; the publisher's page says so. Apps compiled to a single program need nothing extra. If something is missing, the app's loading screen tells you what.
Your data

One folder
Per app, per user

An app keeps its files, its database and its logs in a folder named after the app, in your user account. Programs and data are kept apart, so updating or removing the program normally leaves your data alone.

SystemData folderProgram
Windows%LOCALAPPDATA%\<app id>\%LOCALAPPDATA%\Programs\<App>\
macOS~/Library/Application Support/<app id>//Applications
Linux~/.local/share/<app id>/package or AppImage
Bundle (.osapp)~/.openshell/apps/<app id>/.openshell/~/.openshell/apps/<app id>/

Inside the folder: data/ with the app's own files and database, the logs, and an audit log of everything an assistant did. To remove an app completely, uninstall it and delete its data folder.

With an assistant

Let it use the app
Not your screen

Every installed app can act as a tool for AI assistants that speak MCP, such as Claude Desktop, Claude Code or Cursor. The assistant calls the app's own functions, for example “add a recipe”, instead of clicking around. The app starts in the background if it is not running.

01 · choose

An assistant with MCP

Any client that can start a local MCP server works.

02 · connect

Add the app as a tool

Point the assistant at the app's program with --mcp. The app's runtime panel shows the exact line to copy.

03 · ask

“Add a recipe for flatbread”

The assistant calls the function. Changes you marked as critical wait for your yes.

{
  "mcpServers": {
    "recipe-box": {
      "command": "C:\\Users\\me\\AppData\\Local\\Programs\\Recipe Box\\recipe-box.exe",
      "args": ["--mcp"]
    }
  }
}

Your assistant's own settings describe where this goes. The path is that of the installed app.

You stay in control

QuestionAnswer
What can an assistant do?Nothing, unless the publisher switched agent access on. Then only what the publisher declared as functions. By default it can read, operate the app's interface and call functions that change the app's own data.
What can it never do?Run arbitrary commands, read or write files outside the app, or restart services, unless the publisher has switched that on for the installed app.
Can I approve each step?Yes. Critical actions show a dialog and are denied if nobody answers.
Can I see what happened?Every call is written to an audit log: who, what, when and whether it worked. openshell audit shows it.
More than one device

Use an app
From your other devices

An app can be reached from your laptop, phone or another computer on your network. This is off until the publisher or you switch it on. Each device gets its own pairing, which you can cancel at any time.

pair

One device, one key

Pairing creates a token for that device only. Scan a QR code or paste the token.

limit

Only your network

Restrict access to your home network or your VPN, and encrypt the connection with TLS.

revoke

Take it back

Revoking a device stops its token immediately. Too many wrong tries lock an address out.

Is it safe?

Honest answers

  • Local by default. The app's control interface listens on your own computer only and needs a token. Other devices get in only after you or the publisher enable it.
  • Assistants are fenced in. They get permission scopes, not your computer. Files stay inside the app, and arbitrary shell commands are not possible.
  • Nothing is hidden. Every assistant action is logged. OpenShell is open source under the MIT licence, so anyone can read the code.
  • No tracking by OpenShell. The shell does not collect usage data. What an app itself sends over the internet is up to its publisher.
What OpenShell is not. It is not a sandbox. An app is a program that runs with your user rights, like any program you install, and the permission layer governs cooperating assistants, not malicious software. Install apps from publishers you trust, and keep unsigned installers to sources you know.

Questions

Why does my app say “OpenShell”?

OpenShell is the shell that runs the app: it opens the window, starts the app's services and offers the interface for assistants. The publisher builds the app itself; OpenShell is the part underneath.

Do I need to install OpenShell first?

No. The installer of an app contains everything. You only need the OpenShell command line for portable .osapp files, on servers or in Termux.

How do I uninstall an app?

Like any other app: Settings, Apps on Windows; drag it to the Trash on macOS; use your package manager or delete the AppImage on Linux. Delete its data folder as well if you want it gone completely.

Why does my system warn me when I install?

Installers need to be signed with a certificate the publisher pays for. Unsigned ones trigger a warning from Windows SmartScreen or macOS Gatekeeper. The warning means “unknown publisher”, not “harmful”.

Does it cost anything?

OpenShell is free and open source. Whether an app costs money is up to its publisher.

An app is slow to start or shows an error. What now?

The loading screen shows which part is starting. Right-click the title bar for the runtime panel with each service's state and logs; the publisher can use them to help you.
