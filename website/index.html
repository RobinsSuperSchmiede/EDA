Platforms

Desktop, server, phone
One core runs them all

The runtime, the agent layer and the control API are the same everywhere. A small platform adapter decides which programs may start and how long they may live – so an app built on the desktop also runs on a server or an Android phone.

Platform adapters

Desktop and server start any program. On Android only system tools and programs shipped with the app run – anything else gets an error that says what to use instead.

"platforms": ["desktop", "server"]

Made for phones

Services can pause while the app is in the background and resume when it returns. Services that keep running hold a foreground service, so the phone works as a small always-on server.

"background": "pause"

Remote gateway

Other devices use the app's functions over MCP with a pairing token. Developer tools and the admin token never leave the device, and browser requests are refused.

openshell remote

Status The core and the CLI build for Android and run headless today, for example in Termux. The native Android app with its foreground service is in progress. Planned A device mesh: pair desktop, phone and server with a QR code and deploy from one to the other.

FAQ

Do I have to rewrite my app?

No. Your frontend and backend stay normal projects. OpenShell reads an openshell.json and runs them – the shell is never compiled into your app, so improving the shell improves every app.

How is it different from Tauri or Electron?

OpenShell is built on Tauri 2 and adds what you would otherwise write yourself: process supervision, health checks, logs, a database, hot reload, installers and a standard interface for AI agents. You configure instead of coding a desktop shell.

Do I need a backend?

Only if you want one. A frontend can keep its data in the built-in SQLite database, and AI functions can be plain scripts.

Does it run on Android?

The runtime and the CLI do: they build for Android and run headless, for example in Termux, with static frontends, the built-in database, functions and the remote gateway. The native Android app with a foreground service is in progress.

Which agents and models work with it?

Any MCP client – Claude Code, Codex, Cursor, Copilot – and anything that speaks HTTP/JSON. OpenShell never ships a model; it can detect local providers like Ollama and LM Studio.

Can an agent damage my computer?

Agents only get the scopes you grant per mode, critical actions need your approval, file access stays inside the project, arbitrary commands are impossible and every call is audited.

What does it cost?

Nothing. OpenShell is open source under the MIT license.
